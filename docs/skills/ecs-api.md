# ECS API

The API image is built from `apps/api/Dockerfile` with the pinned Node 24 runtime. The build context excludes `data/`, so operational JSON stays out, and the image does not copy the one-pager `dist/`. The image default bind is `127.0.0.1`. The task sets `API_HOSTNAME=0.0.0.0`, `API_PORT=8787`, and `DB_STARTUP_CHECK=true`.

The cluster is `tropical-nomads`. The service is `tropical-nomads-api`: one Fargate task at 0.5 vCPU and 1 GB, private subnets, no public IP. The repository `tropical-nomads-api` keeps the last 10 images. Logs are `/tropical-nomads/api` for 30 days. The load balancer `tropical-nomads-api` has an HTTPS listener for `api-dev.tropical-nomads.com`. www is not attached.

The task role and the execution role can read the database secret. The execution role can also read `tropical-nomads/api/session`. The container receives `DB_USER` and `DB_PASSWORD` from the database secret, `ACCOUNT_SESSION_SECRET` from the session secret, and `DB_HOST`, `DB_PORT`, `DB_NAME`, and `ASSETS_BUCKET` from the task environment. `ASSETS_BUCKET` is the one private assets bucket. The task role can get, put, and delete only `shop/*` and can list only that prefix. Amplify does not receive the bucket name. The password is not in git. When those database settings exist, the API reads PostgreSQL. When `ASSETS_BUCKET` is set, shop image bytes go to `shop/<productId>` and the product row still stores `/shop/media/<productId>`. JSON remains the one-pager store. The task can open an SSM channel for the private tunnel in [frankfurt-database.md](frankfurt-database.md). A running task keeps its current image until a new API image is built and the service is updated.

From the repo root, `docker build -f apps/api/Dockerfile -t tropical-nomads-api .` builds the image. The next change must not give the task a public IP, attach www to this load balancer, copy `data/operational` into the image, or open the assets bucket to the public.
